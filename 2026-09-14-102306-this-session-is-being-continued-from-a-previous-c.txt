     Shared live Node service for the PHPUnit test suite

     Context

     The webtrees PHP→JS strangler-fig migration has 6 modules bridged to
     server/migration-service.mjs over HTTP. Two of them (FactSortService,
     SurnameTradition) were just cut over (2026-09-12): their native PHP
     fallback was deleted, so they now throw HttpServiceUnavailableException
     if the bridge is unreachable. The remaining 4 (Soundex, GedcomService,
     GedcomExportService::wrapLongLines, GedcomImportService::reformatRecord)
     still fall back to native PHP, and their cutover has been deliberately
     deferred, because 3 of them (Soundex, GedcomService, reformatRecord)
     are invoked with no bridge check from inside
     GedcomImportService::importRecord() (confirmed via grep:
     reformatRecord() at app/Services/GedcomImportService.php:145 calls
     GedcomService::canonicalTag() at line 170; readLatitude()/
     readLongitude() around lines 533/539; Soundex::russell()/
     daitchMokotoff() at lines 712/713/720/721 — up to 4 calls per parsed
     name). importRecord() is called once per GEDCOM record by
     tests/TestCase.php::importTree() (tests/TestCase.php:181-208), which
     is called by 28 test files (confirmed via
     grep -rln "importTree(" tests/). Once native fallback is deleted for
     those 3 modules, every one of those 28 files needs a live, reachable Node
     service or its tests fail outright — with no batching, a single
     importTree() call produces dozens of HTTP round trips. The 4th module,
     wrapLongLines, has a much smaller entanglement — only
     tests/Unit/TreeTest.php's export round-trip test.

     This plan is infra only: it makes it possible for a future,
     separate, per-module decision to cut over any of the 4 remaining modules
     without breaking the 28 dependent test files. It does not cut over
     Soundex/GedcomService/wrapLongLines/reformatRecord themselves — their
     native fallback code is untouched here.

     Two additional gaps found while investigating, folded into this plan:

     - The existing per-file self-managed Node-process pattern (used today by
       4 bridge test files, tracked via a hand-allocated port table
       8193-8200) doesn't scale to 28+ files — spinning up/down that many
       separate Node children is slow and requires a new port per file
       forever. tests/Concerns/UsesMigrationServiceTrait.php's static
       members are also per-using-class copies (its own docblock says so)
       — structurally the wrong vehicle for state that must be shared across
       classes, so it can't just be reused as-is for a shared singleton.
     - .github/workflows/phpunit.yaml sets up PHP only; there is no Node/npm
       setup step anywhere in .github/workflows/, and no CI workflow runs
       npx vitest run at all today. Confirmed server/migration-service.mjs
       imports nothing but node:http and local lib/**/*.js files (no npm
       packages) — CI only needs a node binary, not npm ci/node_modules,
       to run the shared service.
     - A second, separate correctness bug (not just the one originally
       flagged) affects the 4 not-yet-cut-over bridge tests today:
       GedcomServiceBridgeTest.php:82-90, SoundexServiceBridgeTest.php, and
       the analogous blocks in GedcomExportServiceBridgeTest/
       GedcomImportServiceBridgeTest each measure a "native" baseline by
       calling the bridged method before setting their own putenv(...),
       assuming the env var starts unset. Once a shared default service is
       normally running with its env vars always set, that assumption breaks
       for any test running later in the same PHPUnit process — the "native"
       measurement would silently be bridged instead.

     Recommended approach

     1. New class: tests/Concerns/SharedMigrationService.php

     A final, static-only class (not a trait, because it needs state shared
     across classes, not per-class copies) that lazily starts one
     server/migration-service.mjs process for the whole PHPUnit run and
     points all 6 WEBTREES_*_SERVICE_URL env vars at it (all 6, not just
     the 3 entangled with import — this is what makes the other future
     cutovers, e.g. wrapLongLines, need zero new TestCase wiring later).

     final class SharedMigrationService
     {
         private const int PORT = 8090; // reuse the documented dev-default

         private const array ENV_VARS = [
             'WEBTREES_SOUNDEX_SERVICE_URL',
             'WEBTREES_GEDCOM_SERVICE_URL',
             'WEBTREES_SURNAME_TRADITION_SERVICE_URL',
             'WEBTREES_FACT_SORT_SERVICE_URL',
             'WEBTREES_GEDCOM_EXPORT_SERVICE_URL',
             'WEBTREES_GEDCOM_IMPORT_SERVICE_URL',
         ];

         /** @var resource|null */
         private static $process = null;
         private static bool $start_attempted = false;
         private static bool $started = false;

         public static function ensureRunning(): bool
         {
             if (self::$start_attempted) {
                 return self::$started; // O(1) after the first call
             }
             self::$start_attempted = true;

             // proc_open('PORT=8090 node server/migration-service.mjs', ...),
             // same command shape + /health poll loop (25x100ms) as today's
             // per-file code in UsesMigrationServiceTrait. On success: set
             // self::$process, putenv() every ENV_VARS entry to
             // http://127.0.0.1:8090, register_shutdown_function to stop it.
             // On failure: leave everything unset, return false.

             return self::$started;
         }
     }

     Reuses port 8090 (today's documented dev default) rather than adding a
     new number — there is now exactly one port for the whole suite.

     2. TestCase.php hook point

     One line added at the top of the existing importTree()
     (tests/TestCase.php:181):

     protected function importTree(string $gedcom_file): Tree
     {
         if (!SharedMigrationService::ensureRunning()) {
             self::markTestSkipped('Could not start server/migration-service.mjs
     (node/npm unavailable?)');
         }
         // ...unchanged...
     }

     This covers 27 of the 28 files automatically — no per-file opt-in needed,
     mirroring the existing $uses_database precedent but requiring no flag at
     all since importTree() is already the single funnel point. Calling
     markTestSkipped() from inside a helper invoked mid-test is legitimate
     PHPUnit usage (it throws SkippedTestError, which aborts the calling test
     exactly like any other exception) — the same skip message is already used
     verbatim in 4 existing files, just one level shallower.

     For tests/Unit/TreeTest.php::testExportGedcom() (the wrapLongLines
     entanglement): it already calls importTree('demo.ged') on line 299
     before export() on line 303, so the singleton is already started by the
     time export runs — but relying on that ordering implicitly is fragile.
     Add one explicit, idempotent line immediately before the export() call:
     SharedMigrationService::ensureRunning();.

     3. Fix the env-var save/restore bug, generalized to both cases found

     Repurpose tests/Concerns/UsesMigrationServiceTrait.php: drop its
     process-spawning responsibility entirely (no file needs its own child
     process anymore); keep and fix the env-var lifecycle with real
     save-and-restore instead of blank-and-unset:

     trait UsesMigrationServiceTrait
     {
         private static string|false $saved_env_value = false;

         abstract private static function migrationServiceEnvVar(): string;
         abstract private static function
     migrationServiceUnavailableFlagClass(): string;

         private static function overrideMigrationServiceUrl(string $url): void
         {
             self::$saved_env_value = getenv(self::migrationServiceEnvVar()); //
     false if unset
             putenv(self::migrationServiceEnvVar() . '=' . $url);
             self::resetMigrationServiceUnavailableFlag();
         }

         private static function restoreMigrationServiceUrl(): void
         {
             if (self::$saved_env_value === false) {
                 putenv(self::migrationServiceEnvVar());
             } else {
                 putenv(self::migrationServiceEnvVar() . '=' .
     self::$saved_env_value);
             }
             self::resetMigrationServiceUnavailableFlag();
         }
     }

     - The 2 already-cut-over "throws when unreachable" tests
       (FactSortServiceBridgeTest, SurnameTraditionServiceBridgeTest)
       switch from raw putenv(...) + blank-unsetting teardown to
       overrideMigrationServiceUrl('http://127.0.0.1:1') /
       restoreMigrationServiceUrl() — this is the originally-flagged bug fix.
     - The 4 not-yet-cut-over bridge tests (GedcomServiceBridgeTest,
       SoundexServiceBridgeTest, GedcomExportServiceBridgeTest,
       GedcomImportServiceBridgeTest) get the generalized fix: force a true
       native baseline via overrideMigrationServiceUrl('') before measuring
       "native" behavior (since the shared default may already be running and
       set from an earlier test), then rely on the already-running shared
       service (no dedicated port/process of their own) for the "matches
       bridge" half.

     4. Retire the per-file dedicated-port pattern entirely

     Migrate all 6 bridge test files onto the shared singleton, deleting each
     file's own PORT constant and proc_open/startService() block:

     - "Routes through live service" tests: replace the file's own process
       startup with SharedMigrationService::ensureRunning().
     - "Throws/falls back when unreachable" tests: never needed a dedicated
       process at all (already true today for FactSortServiceBridgeTest,
       which never calls startMigrationService()) — just
       overrideMigrationServiceUrl(...) + assert + restoreMigrationServiceUrl().
     - The 4 files not yet using the trait adopt it now (this is the moment
       phase4-cutover-fact-sort-surname-tradition.md anticipated when it said
       they could "adopt the trait during their own cutover phase later" —
       this is the infra phase, not the cutover itself).

     Net effect: the 8193-8200 port table becomes historical; exactly one port
     (8090) serves the whole suite. Rejected alternative: leave the existing
     per-file pattern in place "since it isn't broken" — that would leave the
     exact code paths that have the save/restore bug live alongside the new
     shared default, doubling the ways an env var can leak across tests
     instead of consolidating to one mechanism.

     5. CI workflow: .github/workflows/phpunit.yaml

     Add a Node setup step before the phpunit run (no npm ci needed — the
     service has zero npm dependencies):

           - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 #
     v7.0.0
             with:
               persist-credentials: false

     Pin the action to a SHA with a version comment, matching this file's own
     existing convention (resolve the actual current SHA at implementation
     time, not fabricated here).

     Explicitly separate, optional add-on — not part of this plan unless
     requested: there is no CI workflow running npx vitest run at all
     today (a pre-existing gap, unrelated to this phase). If wanted later, it
     would be a new .github/workflows/vitest.yaml with actions/setup-node +
     npm ci (vitest does need node_modules, unlike the shared migration
     service) + npx vitest run. Flagging this, not doing it here.
